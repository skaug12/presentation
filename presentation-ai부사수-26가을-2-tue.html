Tool · 클로드 코드를 여는 네 곳

클로드 코드를 쓰는 방법은 네 가지입니다

웹페이지

좋은 점 설치가 없습니다. 브라우저에서 바로 열고, 노트북을 닫아도 작업이 이어집니다

아쉬운 점 앤트로픽의 클라우드에서 작업되기 때문에 내 컴퓨터 폴더는 열지 못합니다

데스크톱 앱

좋은 점 내 컴퓨터 폴더를 직접 읽고 고칩니다. 터미널 없이, 고친 부분을 보여줍니다

아쉬운 점 앱이 켜져 있어야 하고, 파일이 어디에 생겼는지는 따로 열어 확인합니다

모바일 앱

좋은 점 리모컨입니다. 밖에서 일을 시켜 두고 결과만 확인합니다

아쉬운 점 내 컴퓨터 폴더는 읽지 못합니다. 처음부터 만드는 작업에는 화면이 좁습니다

VS Code 확장

좋은 점 폴더 · 파일 · 대화 · 명령이 한 화면에 있습니다. 고칠 내용을 먼저 보여주고 예 / 아니오를 받습니다

아쉬운 점 처음에는 화면이 복잡해 보입니다

모바일이나 데스크톱 앱, 웹페이지의 세션을 VS Code에서 이어가긴 어렵습니다. 반대로 VS Code에서 진행하던 세션은 /remote-control을 켜 두면 모바일과 웹페이지에서 이어갈 수 있습니다. 컴퓨터가 켜져 있어야 하고, 데스크톱 앱에는 보이지 않습니다

Tool · VS Code

우리는 VS Code 에서 클로드 코드를 씁니다

VS Code는 개발자가 코드를 쓰고 고치는 데 오래 써 온 프로그램입니다.

개발자가 쓰던 프로그램

파일을 열고, 고치고, 명령을 실행하는 일을 한 창에서 합니다. 비개발자도 같은 화면을 그대로 씁니다

폴더가 왼쪽에 보입니다

클로드 코드가 만든 파일이 어디에 생겼는지 바로 보입니다

왼쪽에 보이는 그 폴더가 워크스페이스입니다

터미널이 안에 있습니다

명령을 적는 창이 같은 화면 아래쪽에 있어, 오류가 나면 그 자리에서 클로드 코드에 붙여 넣습니다

윈도우도 파워셸을 따로 열지 않습니다. VS Code 터미널 하나만 씁니다

한 창에서 끝나는 것이 이 프로그램의 이점입니다 폴더 · 파일 · 명령 · 대화가 같은 화면에 있어 창을 옮겨 다니지 않습니다. 그래서 AI부사수 팀은 VS Code에 클로드 코드 확장을 붙여 씁니다

클로드 코드 채팅창에 /login이라고 적으면 계정을 바꿀 수 있습니다. 열어 둔 폴더는 그대로 있고, 쓴 양만 그때 로그인한 계정에서 빠집니다

구글은 계정마다 따로 붙입니다. 회사 계정으로도 구글을 쓰려면 5단계 로그인 명령을 그 계정으로 한 번 더 합니다

한 계정으로 회사 폴더와 내 폴더를 분리해 쓰고 싶어요

폴더를 두 개 만들어 두고, 일할 때 그중 하나를 엽니다. 파일 → 폴더 열기입니다. 클로드 코드는 지금 열어 둔 폴더만 봅니다

여러 컴퓨터에서 같은 환경으로 쓰고 싶어요

두 컴퓨터에 VS Code와 확장을 깔고 같은 클로드 계정으로 로그인합니다. 본인 컴퓨터면 몇 대든 됩니다

옮길 것은 폴더 하나입니다. 구글 드라이브 또는 깃허브에 폴더를 올려 두고 다른 컴퓨터에서 내려받습니다. 깃허브를 추천합니다. 경로 오류가 없습니다. 대화는 따라오지 않으니 결과는 파일로 저장해 둡니다

갑자기 이전 세션들이 사라졌어요

지워진 것이 아닙니다. 지금 열어 둔 폴더의 대화만 보이는 것이라, 파일 → 폴더 열기로 원래 폴더를 다시 열면 돌아옵니다

그래도 없으면 클로드 코드 창 위의 Session history를 누르고, 목록 맨 아래 Archived sessions를 펼쳐 Unarchive session을 누릅니다. 2주 동안 안 쓴 대화는 거기로 자동으로 들어갑니다

Tips · 사용량

오래 쓰려면 대화는 짧게, 범위는 좁게

클로드는 질문할 때마다 지금까지의 대화 전체를 다시 읽습니다. 대화가 길어질수록 한 번에 쓰는 양이 불어납니다.

주제가 바뀌면 새 대화

한 대화에서 전부 하지 않습니다

길어졌으면 /compact로 지금까지를 요약해 줄입니다

범위를 알려주기

'이 폴더 좀 봐줘' 대신 '(파일명) 의 두 번째 표만'

1회차 '막힐 때' 장의 범위 이야기와 같습니다. 좁을수록 사용량도 줄고 결과도 정확해집니다

한도에 걸리면

몇 시간 뒤 풀립니다

/status로 지금 상태를 볼 수 있습니다

더 정확하게 활용하고 싶다면 Codex를 연결해 교차 검증에 써도 좋습니다. Codex도 VS Code 확장으로 붙습니다. 확장 탭에서 Codex를 검색해 게시자가 OpenAI인 것을 설치합니다. 터미널로 쓰려면 npm install -g @openai/codex 뒤에 codex. ChatGPT 유료 플랜이 따로 필요합니다

Gift · recap 스킬

제 recap 스킬을 드립니다

창을 여러 개 열고 일할 때 지금 뭐가 돌아가고 있는지 정리해 주는 스킬입니다. 파일은 고치지 않습니다.

/recap

이 창 복귀 요약

자리 비웠다 돌아왔을 때

/recap all

열려 있는 모든 창 현황 + 이 창

어느 창이 멈춰 있는지 한눈에

/recap 이름

특정 창만

예: /recap 프로젝트-b3

무엇을 보여주나 뭘 하려던 거였나 · 어디까지 갔나 · 바로 다음에 할 일 · 막힌 것. 네 줄로 나옵니다

Install · 스킬 넣기

받은 스킬을 넣는 법

스킬은 정해진 폴더에 파일을 넣는 것이 설치입니다. 두 곳 중 하나를 고릅니다.

나만 쓸 스킬

~/.claude/skills/<이름>/SKILL.md

어느 폴더를 열어도 됩니다. recap처럼 늘 쓰는 것은 이쪽

이 폴더에서만 쓸 스킬

워크스페이스 안 .claude/skills/<이름>/SKILL.md

폴더를 다른 컴퓨터로 옮기면 스킬도 따라갑니다

넣는 것도 시키면 됩니다 '이 파일을 내 스킬로 넣어줘'라고 적고 파일을 창에 끌어다 놓으면 클로드가 폴더를 만들어 넣습니다. 넣은 뒤 창을 새로 열면 /이름이 잡힙니다

Install · 깃허브에서 가져오기

깃허브에 있는 스킬 모음 가져오기 (k-skill)

남이 만들어 둔 스킬을 그대로 받을 수 있습니다. 한국 생활용 모음집 k-skill이 예시입니다.

명령 한 줄로

npx --yes skills add kitt-ai-com/k-skill --all -g

목록만 먼저 보려면 --all -g 대신 --list. 설치 확인은 npx --yes skills ls -g

그냥 시켜도 됩니다

'이 레포의 설치 문서를 읽고 k-skill 전체 스킬을 설치해줘'

설치 문서가 이 문장을 그대로 붙여 넣으라고 안내합니다

스킬은 쓰기 전에 README를 꼭 읽습니다 남이 만든 스킬은 내 폴더와 계정을 건드립니다. 무엇을 하는 스킬인지, 어떤 로그인이 필요한지 README에 적혀 있습니다. 클로드 코드에 '이 스킬 README 읽고 요약해줘'라고 시키면 됩니다

k-skill에 들어 있는 것 SRT · KTX 예매, 택배 배송조회, 날씨 · 미세먼지, HWP 문서 변환, 한국어 맞춤법 검사 등 서른아홉 가지. 설치 뒤 k-skill-setup으로 로그인과 환경 설정을 마칩니다

지금 제가 하고 있는 일에 어떻게 AI를 적용할 수 있을지 분석하려고 합니다.
두 축은 경험(많으면 1위)과 반복도(많으면 1위)입니다.

저와 인터뷰해서 제가 하고 있는 일 스무 가지를 찾아주세요.
· 질문은 한 번에 하나씩 하고, 제 답을 받은 뒤 그다음 질문을 해 주세요
· '콘텐츠 제작'처럼 덩어리로 답하면, 읽을 파일과 결과물이 있는 크기로 쪼개게 되물어 주세요

일 하나를 찾을 때마다 두 가지를 보기로 띄워 고르게 해 주세요. 제가 직접 적지 않게 합니다.
· 반복도: 매일 / 매주 / 매달 / 드물게
· 경험: 눈 감고 합니다 / 확인하며 합니다 / 매번 찾아보며 합니다 / 해 본 적 없습니다

스무 가지가 모이면 제가 고른 답으로 두 축 순위를 계산해 주세요.
같은 보기를 고른 일끼리 겹치면 그 일들만 다시 보기로 물어 순서를 갈라 주세요.
