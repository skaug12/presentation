/recap

켜둔 클로드 코드 창들이 각각 뭘 하고 있는지 표로 정리

창을 두세 개 켜두면 이런 일이 생깁니다. 자리 비웠다 돌아왔는데 이 창에서 뭘 하던 중이었는지 기억이 안 나거나, 다른 창에서 뭘 하는지 몰라 같은 파일을 두 번 고치거나요. /recap은 클로드가 다른 창의 클로드에게 직접 말을 걸어 상황을 받아옵니다.

  • /recap — 지금 이 창에서 뭘 하던 중이었는지 요약
  • /recap all — 켜져 있는 모든 창이 뭘 하고 있는지 한눈에

만들면서 실제로 덕을 봤습니다. 스킬 파일을 고치는 중에 /recap all을 돌려보니 다른 창이 같은 폴더의 파일 22개를 이미 고치고 커밋까지 한 상태였습니다. 안 물어봤으면 몰랐을 일입니다.

파일 하나를 .claude/commands/에 복사하면 끝입니다. 30분 이상 자리를 비웠다 돌아오면 알아서 요약을 띄워주는 훅도 들어 있는데 이건 선택입니다. 파일은 채널의 recap-스킬.zip.

Remote Control

맥에서 돌고 있는 세션을 폰으로 이어서 조종하기

작업을 클라우드로 옮기는 게 아니라 맥은 계속 돌고 폰이 리모컨이 되는 방식입니다. 그래서 로컬 파일도, 지금까지의 대화 맥락도 다 살아 있습니다. 폰의 Claude 앱이나 브라우저(claude.ai/code)에서 씁니다.

제일 많이 헷갈리는 것. 모바일 앱에서 /remote-control을 치는 게 아닙니다. 거긴 그 명령이 없어서 "그런 명령 없다"는 답이 돌아와요. 세션을 맥에서 열어 명령어를 입력하고, 폰으로 세션을 보냅니다.
cd ~/내작업폴더
claude remote-control --name 아무이름

폰에서 Claude 앱을 열면 세션 목록에 방금 그 이름이 뜹니다. 누르고 대화하면 맥에서 파일을 만지며 작업합니다. 이미 돌고 있던 세션을 넘기고 싶으면 터미널에 따로 칠 것 없이 그 세션 창에 /remote-control만 치면 됩니다.

주의 세 가지

  • 맥이 잠들면 끊깁니다 → caffeinate -i를 따로 띄워두세요
  • 폰과 맥이 같은 Claude 계정이어야 합니다 (첫 연결 때 기기 등록 한 번)
  • 최신 버전이어야 합니다 → claude update

4회차 · 8월 2일

PRD

"무엇을, 왜 만드는가"를 정의하는 개발 착수 문서

기획자가 쓰고 개발·디자인이 읽습니다. 보통 들어가는 것:

  • 배경/문제 정의 — 왜 지금 이걸 하나
  • 목표와 성공지표 (예: 가입 전환율 12%→15%)
  • 타깃 사용자 / 유즈케이스
  • 요구사항 (기능별 상세, 우선순위 P0/P1/P2)
  • 화면 흐름·와이어프레임
  • Out of scope — 이번에 안 하는 것
  • 리스크, 의존성, 일정

실행 지향입니다. 만들 것의 스펙이 핵심이고 팀 내부에서만 돕니다. 길고 상세할수록 좋다는 오해가 있는데, 실제로는 "합의된 결정"만 남기고 나머지는 링크로 빼는 게 낫습니다.

4회차 · 8월 2일

PR/FAQ

아마존의 Working Backwards — 만들기 전에 보도자료를 먼저 쓴다

"다 만들어서 출시했다고 치고" 보도자료를 씁니다.

  • Press Release (1~1.5장) — 출시일자, 헤드라인, 부제, 요약 문단, 고객 문제, 해결책, 내부 임원 인용구, 고객 인용구, 시작 방법
  • 외부 FAQ — 고객이 물어볼 것 (얼마인가, 어떻게 쓰나, 기존 거랑 뭐가 다른가)
  • 내부 FAQ — 팀이 물어볼 것 (시장 규모, 수익 모델, 기술적 난제, 왜 우리가, 왜 지금, 실패하면?)

검증 지향입니다. 스펙이 아니라 "이게 고객에게 매력적인 이야기가 되는가"를 먼저 시험합니다. 보도자료가 지루하면 그 제품도 지루한 것 — 그러면 만들지 않습니다. 아마존에선 회의 시작 때 다같이 침묵으로 읽고 토론합니다.

4회차 · 8월 2일

worklog와 daily 노트

작업 중 실시간 기록(협업용)과 하루 끝 회고(기록용)를 나눠 쓴다

worklog/ — 업무일지

  • 위치: worklog/YYYY-MM-DD.md
  • 언제: 세션 시작할 때 목적을 먼저, 이후 편집할 때마다 자동 누적
  • 누가: 목적은 사람이 직접, 이후 줄은 훅이 자동
  • 목적: 여러 명이 같이 쓰는 레포에서 "누가·왜·무엇을 고쳤나" 추적
## session:8ef7d8e7 — 슬기
- 목적/왜: ...
- 무엇을: 1. ... 2. ...
- 09:25 [Edit] scripts/adjust_season_stock.py   ← 훅 자동
### 결과 (09:25 완료)
- ...

daily/ — 데일리 노트

  • 위치: daily/YYYY-MM-DD.md
  • 언제: 하루 마무리에 /run-daily-note를 실행할 때 한 번
  • 누가: 클로드가 자동으로 수집해서 작성
  • 목적: 하루 전체를 서사로 정리하고 커밋·푸시까지 마감

구조는 "오늘 완료한 작업"(불릿 요약) → "작업 흐름"(세션별로 내 프롬프트 → 클로드 처리 → 의사결정 → 결과 → 미해결). 그 뒤에 미리알림 정리·출석 확인·커밋/푸시가 이어집니다.

어디에 뭘 쓰나

  • 작업 시작 직전의 목적 → worklog
  • 파일 수정 흔적 → worklog (자동)
  • 세션 끝의 결과·미해결 → worklog의 "결과" 항목
  • 하루 전체 서사·의사결정 이유·다음 액션 → daily (/run-daily-note)
  • 여러 날 걸치는 큰 작업의 진척 → PROGRESS.md
