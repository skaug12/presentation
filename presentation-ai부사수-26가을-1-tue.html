만든 사람

Boris Cherny · Anthropic

회사 안에서 만들어 쓰던 것이 그대로 우리가 쓰는 도구가 됐습니다

채팅창이 할 수 있는 것

대화만 합니다

답을 받아서 내가 다시 옮겨 적어야 합니다

터미널이 할 수 있는 것

파일을 읽고, 고치고, 돌리고, 확인합니다

내 컴퓨터 안의 진짜 파일을 다룹니다

그래서 무엇이 달라지나 답을 받아서 내가 옮겨 적는 게 아니라, 일이 끝난 상태를 받습니다. "알려주는 AI"에서 "일을 하는 AI"로 넘어가는 자리가 여기입니다

Concept · ChatGPT · Gemini와의 차이

"알려주는" AI와 "실행하는" AI

같은 "200개 상품 데이터 분석해줘"를 시켰을 때 무엇이 다른지 보시면 됩니다.

ChatGPT · Gemini — 알려주는 AI

  • 파일을 올리면 요약해서 글로 알려줍니다
  • 양이 많으면 일부만 보고 대략 답합니다
  • 결과를 복사해 엑셀에 다시 붙여넣어야 합니다
  • "답변"은 주지만 실행까지는 안 합니다

클로드 코드 — 실행하는 AI

  • 내 컴퓨터의 파일을 직접 열어서 처리합니다
  • 200개 전부 빠짐없이 훑습니다
  • 분석 결과를 쇼핑몰에 바로 반영까지 합니다
  • "답변" 대신 "결과물"을 만들어 줍니다

클로드 코드 안에 Claude가 들어 있습니다

가입하면 ChatGPT처럼 대화하는 기능이 이미 포함되어 있습니다

쓰던 대화도 옮길 수 있습니다

ChatGPT·Gemini에서 나눈 대화 내용을 가져올 수 있습니다

구독 하나로 정리됩니다

다른 서비스만의 강점이 특별히 없다면 이것 하나면 충분합니다

Concept · 할루시네이션

AI는 왜 틀릴까 — 같은 뿌리, 다른 증상

둘 다 "다음에 올 말을 확률로 예측해" 글을 씁니다. 그래서 그럴듯하지만 틀린 답이 나옵니다. 뿌리는 같고, 틀렸을 때 드러나는 방식이 다릅니다.

Claude (채팅)의 실수

무엇을 어디서 틀렸는지 알 수 없습니다

숫자와 사실을 그럴듯하게 지어냅니다 · 검증할 수단이 없어 고칠 기회가 적습니다 · 위험: 그럴듯한 오답을 사실로 믿게 됩니다

클로드 코드 (실행)의 실수

틀리면 에러와 실패 기록이 남습니다

시행착오를 반복하며 스스로 고쳐 갑니다 · 위험: 통과는 하는데 미묘하게 틀린 결과가 나올 수 있습니다

한두 번 물어가며 정답에 가까워지는 것 시간 끌기가 아닙니다. 실행해 보고 정보를 모아 추측을 교정하는 과정입니다. 확인할 수단(실제 파일·에러·비교 대상)을 줄수록 빨라집니다

Concept · 비유

같은 표를 맡기면 — 두 사람 비유

같은 매출 표에 "지난달 대비 증감률 뽑아줘"라고 시켜 봅니다. 둘은 서로 다른 종류의 실수를 합니다.

Claude (채팅) = 암산 천재, 검산은 안 합니다

"약 12% 증가한 것 같아요" (실제로는 9%)

큰 표를 끝까지 안 보고 어림합니다 · 틀려도 자신 있게 말해 티가 안 납니다 · 맞는 질문에 틀린 답

클로드 코드 = 검산은 완벽, 가끔 엉뚱한 걸 계산합니다

정확히 9.3%를 냅니다. 다시 돌려도 같은 값입니다

단, "지난달"에 취소 주문을 넣었다면? 그 잘못된 전제로 정확한 9.3%를 냅니다 · 틀린 질문에 맞는 답

그래서 사람이 챙길 것이 다릅니다 채팅에는 검산(숫자가 맞는지)을, 클로드 코드에는 전제 확인(무엇을 계산할지)을 짚어 주셔야 합니다

Core Concept · 스킬과 에이전트

스킬과 에이전트, 쉽게 이해하기

스킬 = 레시피

"김치찌개 만들어줘" — 정해진 레시피대로 만들어 주는 것입니다.

/수강확인증-생성 이라고 치면 정해 둔 순서대로 확인증을 만듭니다. ChatGPT를 쓰셨다면 "지침"이나 "프로젝트"를 한 번에 묶어 실행한다고 보시면 됩니다.

/수강확인증-생성   # 미리 정해둔 순서대로 자동 실행

에이전트 = 요리사

"냉장고에 있는 거로 저녁 차려줘" — 열어보고, 확인하고, 메뉴를 정하고, 요리까지 알아서 합니다.

필요하면 스킬(레시피)을 여러 개 꺼내 씁니다. 중간중간 "이렇게 할까요?" 확인을 받으며 진행합니다.

Concept · 스킬이란

"스킬"이 뭔지 실물로 보면

일하는 순서를 글로 적어 둔 파일 하나입니다.

# 검수 스킬: 안내문을 발송 전에 점검한다

1. 안내문 파일을 읽는다
2. 표기 규칙 파일과 대조한다 (날짜는 M월 D일, 금액은 천 단위 쉼표)
3. 어긋난 곳을 고치지 말고 목록으로만 내놓는다
4. 위치와 이유를 함께 적는다

# 절대 하지 않을 것: 안내문 본문을 직접 수정하지 않는다

3번과 마지막 줄을 꼭 보세요. 고치게 두면 무엇이 바뀌었는지 모릅니다. 판단은 사람이 하고, 찾는 일만 넘깁니다. 이 방식을 human in the loop라고 부릅니다. 석 달 내내 이 원칙으로 갑니다.

Core Concept · 용어

요즘 자주 듣는 세 단어 — RAG · 하네스 · 아티팩트

RAG · 찾아보고 답하기

답하기 전에 외부 자료에서 관련 내용을 먼저 찾아온 뒤 그걸 보고 답합니다. 관련 페이지를 펼쳐 놓고 시험 보는 것과 같습니다

제 경우 = 메모리 + 옵시디언 · 멤버십 시트 · 캘린더 / 여러분 경우 = 사내 규정 파일 · 지난 보고서 · 고객 목록

하네스 · 엔진을 자동차로

모델(엔진)을 감싸 실제로 일하게 만드는 바깥 장치입니다. 도구를 쥐여주고, 결과를 돌려받고, 얼마나 자주 피드백과 기억을 남기느냐로 결과가 갈립니다

제 경우 = 클로드 코드 + 132개 스킬 + 권한 + 외부 서비스 연결

아티팩트 · 남는 결과물

작업이 만들어 내는 실제 산출물입니다. 문서 · 이미지 · 발표 자료처럼요

제 경우 = 레터 · 핸드아웃 · 쇼핑몰 HTML · 공지 · 대시보드 / 여러분 경우 = 보고서 · 제안서 · 안내문 · 정리된 시트

한 줄 그림 RAG가 무엇을 알고 무엇을 지킬지 공급하고 → 하네스가 받아서 일을 시키고 → 그 결과로 아티팩트가 나옵니다. 클로드 코드 하나에 이 셋이 다 들어 있습니다

Case 1 · 절차 파일

절차를 글로 적어 둔 것이 전부입니다

코드가 아니라 순서입니다. 이걸 읽고 클로드 코드가 스크립트를 만들었고, 지금은 그 스크립트가 돕니다.

# 인스타 저장됨 → 옵시디언 노트

1. 이 작업 전용 브라우저 프로필로 로그인한다 (내 실제 브라우저는 건드리지 않는다)
2. '저장됨' 목록을 끝까지 내려 새 글만 고른다 (이미 받은 글은 건너뛴다)
3. 글마다 캡션과 이미지를 받고, 이미지 속 글자는 OCR로 읽어 본문에 붙인다
4. 내용을 읽고 16개 폴더 중 하나에 넣는다
5. 확신이 없으면 _inbox 폴더에 둔다 (억지로 분류하지 않는다)

# 절대 하지 않을 것: 남의 계정을 긁지 않는다. 내가 저장한 것만

5번이 사람 자리입니다. _inbox에 쌓인 걸 제가 폴더로 옮기면, 그 옮김이 다음 분류의 학습 데이터가 됩니다. 제 취향을 설명하지 않았는데 폴더가 취향을 배웁니다. 이게 "암묵지가 데이터로 쌓인다"의 실물입니다.

Case 1 · 깨진 것 · 8월 22일

예시 1 · 깨졌던 것 — 폴더가 틀렸습니다

처음 만든 방식

인스타 컬렉션 이름을 그대로 폴더로 썼습니다

편했습니다. 그런데 컬렉션은 저장할 때의 기분이지 내용이 아니었습니다. "나중에"라는 컬렉션에 요리·기술·밈이 다 들어 있었습니다

고친 방식

캡션과 OCR 내용을 읽고 분류하게 바꿨습니다

971편을 한 번에 재분류. 컬렉션은 분류 근거에서 뺐습니다

남긴 규칙

자동 분류는 확신 있는 것만. 나머지는 사람 앞으로

로컬 분류기는 65%만 자동으로 놓고 35%는 _inbox로. 정확도보다 틀린 걸 조용히 넣지 않는 것이 중요했습니다

여기서 배운 것 처음 설계가 틀리는 건 당연합니다. 틀렸다는 걸 알 수 있게 만들어 두는 것이 설계입니다. 4회차 "잘하는 일을 더 잘하려면"이 정확히 이 이야기입니다

Security · 설치 전에 알아둘 것

AI에게 뭘 말해도 되나요?

클로드 코드는 내 컴퓨터에서 작업하지만, 내가 입력한 내용은 인터넷을 통해 Claude 서버로 전송됩니다. 그래서 보내는 내용을 구분해야 합니다.

말해도 되는 것

  • "매출 시트에 컬럼이 다섯 개 있어" (구조만 설명)
  • "이 엑셀을 월별로 분류해줘" (작업 요청)
  • "마케팅 카피 초안 써줘" (콘텐츠 작성)
  • "경쟁사 가격 비교해줘" (공개 정보)

절대 말하면 안 되는 것

  • 고객 개인정보 (이름 + 전화번호 + 주소)
  • 회사 사내 시스템 비밀번호
  • 미공개 재무제표, 인사 정보
  • 주민번호, 카드번호, 계좌번호

비밀번호는 이렇게 보관합니다 토큰·비밀번호는 별도 파일에 저장합니다. 클로드 코드에게 "비밀번호 보관 파일 만들어줘"라고 한 뒤, 생성된 파일을 직접 열어서 값을 넣고, 이후에는 "그 파일에서 읽어서 써"라고 시킵니다. 이렇게 하면 대화에 비밀번호가 노출되지 않습니다.

Philosophy · 직접 해봐야 내 것이 됩니다

책을 사는 것만으로 지식이 되지 않듯
